    Max-Heap Relevance Ranking (PriorityQueue)

    Documents are ordered dynamically using a Binary Max-Heap with deterministic alphabetical tie-breaking.

    Insert: O(log N) • Extract-Max: O(log N) • Top-K: O(K log N)

    Max-Heap Comparator Mechanics & Tie-Breaking
    1
    Primary: Frequency Score (Descending)

    Score is calculated from keyword occurrences in the document content and filename. Max-Heap root holds the highest relevance score.

    Integer.compare(b.getScore(), a.getScore())
    2
    Secondary: Lexicographical Tie-Breaker

    When two documents share the exact same score, ties are broken deterministically by document file name in alphabetical order.

    a.getFileName().compareToIgnoreCase(b.getFileName())
    3
    Top-K Efficiency Advantage

    Extracting the top $K$ results takes $O(K \log N)$ rather than sorting all $N$ documents ($O(N \log N)$), saving compute on large document sets.

    Search History Stack (LIFO: Last-In, First-Out)

    Maintains every query entered during the session. Push & Pop operations execute in $O(1)$ constant time.

    Stack DSA Properties

    • Data Structure: java.util.Stack<String>
    • Principle: Last-In, First-Out (LIFO)
    • push(query): Inserts on top of stack in $O(1)$
    • peekLatest(): Inspects most recent query without removal in $O(1)$
    • Traversal: Top-to-bottom ($size-1 \to 0$) so latest searches appear first

    Recent Searches Queue (FIFO: First-In, First-Out)

    Bounded sliding window buffer with a fixed capacity of 5. Automatically evicts oldest items from head upon capacity overflow.

    Capacity: 5 Items • Enqueue: O(1) • Evict: O(1)

    FIFO vs LIFO Distinction (Viva Focus)

    STACK (History.java)

    LIFO

    Unbounded capacity. Newest elements on top. Users inspect recent searches first.

    QUEUE (RecentSearchQueue.java)

    FIFO

    Fixed capacity of 5. Oldest elements at head get evicted (poll) when new queries arrive (offer).
